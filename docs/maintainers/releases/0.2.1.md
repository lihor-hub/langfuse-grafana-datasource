# v0.2.1 Grafana review candidate

This prepares a new **unsigned pre-release for catalog review**, not a signed
or catalog-approved installation. Tagging, GitHub release publication and
updating the Grafana submission each require explicit maintainer approval.
Do not replace any v0.2.0 asset.

## Review changes

- Handle an absent Query kind Combobox option without crashing, changing the
  selected kind, discarding inactive query drafts or running a query.
- Apply the same handling to the observation Log body selector.
- Remove development instructions, pre-release notices, project/release status,
  planned compatibility and maintainer-only sections from the catalog README.
- Use the unmodified official Langfuse color icon for both plugin icon sizes,
  with source attribution and the independent-project disclaimer.
- Include the merged Grafana 13.3/React 19 frontend build updates and compatible
  development dependency updates already recorded in the changelog. The plugin
  uses the host Grafana React at runtime; the Grafana 12.3 minimum is unchanged.

The signing-tool v4/Node 24 migration merged while this candidate was being
prepared and is included. Use Node 24.15.0 or newer within 24.x as required by
this candidate's package. This is a development/CI toolchain requirement, not a
change to the Grafana or Langfuse runtime requirements. The candidate remains
unsigned; upgrading the signing tool does not authorize signing.

## Focused reviewer checks

Use a self-hosted Langfuse v4 instance, or the synthetic development stack in
[Mock Langfuse](../../mock-langfuse.md). Follow
[onboarding](../../onboarding.md) for installation and safe configuration.
Do not copy real credentials or customer observations into review evidence.

1. In Explore, select this data source and the **Observations** query kind.
2. Type **Score** into **Query kind**, then press Enter without choosing an
   option. Confirm the observation editor remains usable and the query draft
   has not changed. Selecting **Scores (table)** explicitly must still work.
3. Return to observations with **Logs** format. Type **status** into **Log
   body**, then press Enter without choosing an option. Confirm the editor
   remains usable and the prior log-body choice is retained. Selecting a valid
   option explicitly must still update it.
4. Confirm observation filters, the Table/Logs controls and Advanced JSON still
   work and no unexpected-error screen appears.
5. Inspect the README inside the ZIP: the removed development/release sections
   must not appear. Confirm the official Langfuse color mark appears in Grafana.
6. Run the existing metrics, observations, scores, variables, configuration and
   dashboard browser scenarios across the complete CI Grafana matrix.

## Artifact and evidence gates

- Build and package from the reviewed release commit. Preserve the exact
  CI-tested build bytes rather than substituting a later local webpack build.
- Verify one top-level ZIP directory, `lihorhub-langfuse-datasource`, version
  `0.2.1`, referenced images/docs, the corrected README and the official icon.
- Retain the source commit, Actions run and artifact ID, upstream metadata
  validation output, browser matrix results, SHA1 and SHA256 with the release.
- Obtain fresh dependency/security evidence; remaining findings are not waived.
  Local validation and metadata-only CI do not imply a passing full
  source-enabled validator or catalog approval.
- The previous release's real-host review results are useful context, not proof
  of this exact candidate on every Langfuse Cloud or self-hosted environment.
- Finish the clean-install and other gates in the
  [release runbook](../releasing.md) before publication. No production signature
  policy may be weakened to install an unsigned review candidate.

After the immutable artifact is published with approval, update the existing
submission in **grafana.com → My Plugins** using the new ZIP URL and its SHA1.
Then reply to support ticket **#252294**; do not claim the submission was
updated until the portal confirms it.
